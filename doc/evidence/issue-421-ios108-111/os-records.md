- アラームタブ → アラームを開き「アラーム編集」画面へ遷移
- 時刻ホイール（午前/午後・時・分）が最初から展開状態で表示
- ホイールはカード内中央に配置、ラベル行・休止日行・スヌーズ行と重ならない
- 証跡: `issue421-111-wheel.annotated.png`（元画像 `ios-now2.png` 8:34 JST）

## 行108（2分後アラーム→アプリ終了→ロック→停止）→ 部分検証（残課題あり）
実施できた部分:
- アプリを terminate した状態で「テストで鳴らす（10秒後）」を実行 → AlarmKit のシステムアラートが発火
  - 「Calendar Alarm / テスト鳴動」＋スヌーズ(Zzz)・停止(✕)ボタンが表示（8:43, 8:48 の2回確認）
  - 証跡: `issue421-108-alert.annotated.png`（元画像 `ios108-fire2.png` / `ios108-ringB.png`）
- アラート停止後、アプリ内「最近の鳴動」に「11/19 午後8:42 停止 テスト鳴動」と記録 → 停止操作が有効に機能
- 8:42 発火後 5分以上経過しても再鳴なし（8:48 の発火は別途手動で起こした2回目）

未達成（ブロック事項・要人間追試）:
1. スケジュール型アラーム（2分後）の経路: 8:38 の1回のみアラームを作成したが「次 11/20」へスキップ
   - 原因: そのアラームの「休止日」に 2026/11/19（当日）が入っていたため当日発火しない仕様
   - 検証で作った当該アラームは削除済み（アラーム画面「アラームなし」を確認）
2. ロック画面上での停止操作: 実機iOSでは XCUITest(WDA) がロック中の画面を駆動できない
   - `mobile: pressButton lock` 非対応、`mobile: lock` も実機では利用不可
   - WDA自体がロック中操作不能のため、ロック中の停止ボタン操作は自動化不可
   - 残る確認: 「ロックを解除せずアラートの停止ボタンを押せるか」は人間の手での10秒確認が必要
3. WDA の安定性: 当該端末で WDA が断続的にクラッシュ（socket hang up）。
   Mac のディスク逼迫（容量0〜数百MB が繰り返し発生）が xcodebuild/WDA 起動を不安定にした疑い。
   キャッシュ削除後も断続クラッシュが残った。
