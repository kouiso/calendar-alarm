# issue #421 行114 iOS 実機検証（表示側のみ・音なし）

- 端末: iPhone「Miyu」(iPhone 12 / iOS 27.2 / UDID 00008101-000911A61430001E)
- アプリ: com.calendaralarm.ios
- 駆動: WebDriverAgent 16.12.8 経由の UI 操作と画面キャプチャ
- 実施日時: 2026-11-19 (JST 23:53〜翌0:00 端末表示)

## 検証した範囲

行114「将来の予定を作り端末の時間帯を変えると、新しい時間帯で表示・発火する」
のうち **表示側のみ** を検証。発火確認は音が出るため本検証の対象外。

## 手順と結果

1. 変更前: アプリ予定一覧で「あつ森」は 午後10:00 (JST) 表示。ステータスバー 15:53 → `01-before-jst.png`
2. 設定→一般→日付と時刻で「時間帯を自動的に設定」OFF、時間帯の都市を「ロンドン」へ変更。時間帯 GMT+00:00、ステータスバー 7:00 → `02-settings-london.png`
3. アプリへ戻ると同一予定が 午後1:00 (GMT) 表示に更新。JST 22:00 = GMT 13:00 で時差換算どおり。ステータスバー 6:56 → `03-after-gmt.png`
4. 検証後「時間帯を自動的に設定」を ON に戻し、東京 (日本標準時) に復元済み → `04-restored-tokyo.png`

## 判定

- 表示: PASS。タイムゾーン変更に追従し予定表示時刻が新しい時間帯で正しく描画される
- 発火: 未検証 (発火時に音が出る行のため、持ち主の明示許可待ち)
