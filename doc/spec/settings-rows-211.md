# 設定画面の行ごとの棚卸し（#211）と「タイトルコード」の比較（#203）

SBI/PBI GitHub Issue #211（設定画面の不明瞭な機能群の棚卸し）と #203（タイトルコードの必要性）の成果物。コードの変更は含まない。
基準は master `3d251e4`（初版は `89af2d1`。その間に変わった設定・鳴動・共有ロジック・iOS・板のファイルは `AgendaScreen.kt` の1行だけで、引いた行番号は動いていない）、作成日 2026-11-14。コードとデザインの板を読んで確認した行だけを根拠にした。実機・エミュレータでは動かしていない（未確認と書いた所は読み切れていない）。

パスは `A` = `androidApp/src/main/java/com/calendaralarm/`、`I` = `iosApp/iosApp/`、`S` = `shared/src/commonMain/kotlin/com/calendaralarm/shared/`、`D` = `design/project/`。
`A:ui/SettingsScreen.kt` は長いので、以下の表では `SS` と略す（`A:ui/SettingsScreen.kt` のこと）。iOS の設定画面は `I:SettingsView.swift`（`SV` と略す）。

## 0. 先に結論

- 報告された「時計→ベル→タグ→参加状態→予定種別→人物連携」の各行は、どれも実装にぶら下がっていた（ダミー・未接続の行は見つからなかった）。「存在を直ちに不要と断定しない」という #211 の方針どおり、**削除の根拠が出たのは今のところ「タイトルコード」だけで、その判断も #203 の持ち主の決定待ち**（§3）。
- 見えにくさの原因は機能の有無ではなく **見出しの無い行・同じアイコンの使い回し・言葉の不一致**。同じアイコンが複数行に使われている（§1.1）。
- Android と iOS で**行の中身が食い違う所のうち、主なものは2つ**（全体は §2）: (a) 「通知タイミング」の選択肢（Android の既定の行は 開始時/5/10/15、iOS は 開始時/5/10/15/30）と表記（Android「5分」、iOS「5分前」）。30 が無いのは Android の既定の行だけで、同じ Android のカレンダー行 `SS:810`・アカウント行 `SS:1807` には 30 がある、(b) 天気の4行が iOS では2枚のカードに割れている。
- Android にだけある機能は意図どおり（板に「iPhone にこの項目は無い」と書いてある: #148・#150）。iOS にだけある設定行は無い（`#if DEBUG` の虫マークを除く）。

## 3. #203 タイトルコードの比較

### 3.1 何をするか

予定のタイトルに、登録した言葉が**含まれていたら**、その予定の鳴らし方を強制する。

- 「必ず鳴らすコード」に一致 → アラームにする。「鳴らさないコード」に一致 → 鳴らさない。大文字小文字を区別しない部分一致（`S:model/Models.kt:34-38` `alwaysMatch` / `neverMatch`）。正規表現ではない。
- 優先順位: **予定個別の上書き ＞（先に外れるもの）＞ 鳴らさないコード ＞ 必ず鳴らすコード ＞ ルール（カレンダーの上書き → アカウント → アプリの既定）**（`S:logic/AlarmExpander.kt:310-330` `resolveActions`。ルールの決まり方は `A:data/AlarmRepository.kt:283-289`）。
- 「先に外れるもの」は、タイトルコードを見る前に外れる絞り込み: 招待の返事・予定の種類（`passesEventFilters` `AlarmExpander.kt:80`、定義 `:143-152`）、終日 OFF（`:84`）、使わないカレンダー・アカウント OFF。`resolveActions` は `:97` で、これらを通った予定にだけ呼ばれる。Android の一覧も同じ順で、`A:data/AlarmRepository.kt:304-309` がカレンダー OFF・終日 OFF・アカウント OFF・絞り込みで先に鳴らさない側へ倒す。**つまり「必ず鳴らすコード」でも、辞退した招待・切った種類・使わないカレンダーの予定は鳴らない**（個別に「アラーム」を選んだ予定は絞り込みを越える `:150`）。鳴らさない側を優先する理由はコメントに「抑止を破る方が危ない」。
- 「適用範囲」: 両方／開始のみ／通知分のみ。開始時刻の鳴動と「○分前」の通知で別々に当てられる（`applyToStart`、`applyToReminders`）。
- 上限: 各リスト最大15個。**1つ20文字は Android だけ**（`SS:1154` `CodeEditor`、`SS:1164`）。iOS は空白を除いて、空・重複・15個超を止めるだけで、文字数の制限は無い（`I:TitleCodesSheet.swift:74`）。重複と空文字は追加できない（2OS とも）。
- 予定一覧の表示も同じ関数を使うので、一覧の「鳴る/鳴らない」の表示と実際は一致する（`AlarmExpander.kt:344-351` `silencedWithoutOverride`）。
