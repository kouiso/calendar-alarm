# Calendar Alarm テスト仕様書

アラーム系アプリのテスト方針。コードで検証できるもの（単体テスト）と、OS境界・実鳴動が絡むもの（手動E2E）に分ける。

## 基本方針（アラームアプリの作り方）

1. **ドメイン層は shared (KMP) に寄せて単体テスト可能にする。** 時刻展開・オフセット・種別判定・フィルタは全て `shared/src/commonTest` で検証する。OS API を直接呼ばない純粋関数にしておくことが前提。
2. **OS境界（AlarmKit / AlarmManager / 通知）は単体テストにしない。** 鳴動・停止・スヌーズはシミュレータ/実機で**実際に鳴らして止める**まで確認する。「コードが正しそう」は完了条件にしない。
3. **フォールバック経路も検証する。** Google連携なし・通信失敗・権限拒否の各パターンで「以前どおり鳴る」ことを確認する。

## 単体テスト（`./gradlew :shared:jvmTest`）

| 対象 | ファイル | 観点 |
|---|---|---|
| 鳴動展開 | AlarmExpanderTest | 14日ホライズン・繰り返し・オフセット・容量制限 |
| 通知ルール | NotificationRuleSpecTest | カスタムオフセット・ルール照合 |
| イベント種別 | EventTypeTest | googleEventType 写像、タイトル分類、resolveEventType の正本優先/フォールバック、EventTypeFilter の allows |

新しい分類・フィルタ・スケジュールロジックを足したら、同じ shared 層にテストを追加すること。

## 手動E2E（iOS sim / Android 実機）

| # | 手順 | 期待結果 |
|---|---|---|
| 1 | 近い将来のカレンダー予定にアラームを鳴らす →「停止」を1タップ | OS鳴動が止まり画面が閉じる。音だけ残らない |
| 2 | 鳴動中に通知・画面を全部閉じる | 鳴動画面の停止ボタンが引き続き効く（止める術が残る） |
| 3 | 鳴動中に resync/カレンダー同期が走る | 鳴動が継続する（勝手に止まらない） |
| 4 | 「スヌーズ」→ 指定分後 | 再鳴動する |
| 5 | アラーム編集シートを開く | 時刻ホイールが常時展開・中央表示・行に重ならない |
| 6 | 設定でイベント種別（誕生日/不在/勤務場所/タスク/予定）を OFF → 該当予定の時刻 | 鳴らない。ON に戻すと鳴る |
| 7 | Google連携 → eventType が API 正本で判定される（タイトルと無関係な予定で確認） | 連携中は API 値、解除後はタイトル判定へ戻る |
| 8 | 権限拒否・機内モード | クラッシュせず、未連携時と同じ挙動 |

## 検証の証跡

鳴動・UI系の修正は**実際に鳴らして止めた動画/スクショ**を PR に添付する（`!bad` 反省ノート由来のルール）。
